FOCUSED DIAGNOSTICS

From address range to useful evidence.

Choose a CIDR target, select the right level of inspection, and retain only responsive services instead of scrolling through thousands of timeouts.

01

Three scan modes

Start with core services, choose advanced categories, or define a small custom port set.

02

Bounded concurrency

Control probe concurrency and timeout while the engine respects a fixed diagnostic budget.

03

IP-first reports

One summary block per responsive IP, with every detected TCP or UDP service shown directly below it.

04

Portable evidence

Every scan receives a unique report number and can be exported as CSV or grouped PDF.

WORKFLOW

A calmer way to inspect a subnet.

  1. 01

    Define the scope

    Enter a host or CIDR range that you own or are authorized to inspect.

  2. 02

    Choose the signal

    Use Basic, Advanced, or Custom mode and tune timeout or concurrency when needed.

  3. 03

    Run locally

    The device performs the diagnostic directly. No OpsHome cloud account is required.

  4. 04

    Read the report

    After completion, the app opens a numbered report with counts, exposure context, and IP-grouped results.

REPORT ANALYSIS

Results arranged around decisions, not probes.

The report separates the scan scope from responsive evidence, highlights remote-management services such as RDP, VNC, SSH and WinRM, and flags sensitive services for configuration review.

Context, not a vulnerability verdict.An open port shows that a service responded. It does not by itself prove that the service is vulnerable or publicly exposed.

PRIVACY FIRST

Network diagnostics stay local.

Port Inspector Pro does not require an account or upload scan targets and results to an OpsHome backend. Reports leave the device only through an export action you initiate.

  • Diagnostics run from your iPhone or iPad
  • Responsive results are stored in the app’s private container
  • History retention is under your control
